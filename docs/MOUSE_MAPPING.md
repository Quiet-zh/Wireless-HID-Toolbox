# 鼠标按键映射

版本 **1.25.0** 起，主界面右上角新增 **🖱 按键映射**。

它做两件事：

1. **拦截**已启用鼠标上的指定物理按键，原事件不再传给系统；
2. 改为触发本工具定义的**事件**（鼠标功能 / 键盘组合 / 打开应用 /
   组合事件 / 宏定义 / 语音输入）。

> 只读查询设备、不改 DPI/灯效；拦截发生在用户态 Low-Level Mouse Hook，
> 不需要驱动、不需要管理员权限。

## 1. 打开与保存

- 主界面右上角 **🖱 按键映射**
- 或：**⚙ 设置 → 工具 → 鼠标按键映射**
- 或：`python main.py --tool mouse-map`

左侧是**所有已连接鼠标**（离线但配置过的设备也会列出来，标 `○`）。
选择一台鼠标后：

| 操作 | 说明 |
| --- | --- |
| 启用此鼠标的映射 | 只拦截这台鼠标；其他鼠标不受影响 |
| 添加映射 | 选择按键、触发方式、事件类型，配置具体动作 |
| 修改 / 删除 | 选中表格行后操作；双击行等同修改 |
| ▶ 测试 | 立即执行一次当前动作（不经过鼠标按键） |
| 启用按键映射 | 全局开关；保存到 `mouse_map.json` |

**保存是即时的**：每次添加/修改/删除都会写盘。
配置窗口打开期间，后台映射会自动暂停；**关闭窗口后自动恢复**——
这是为了避免把左键映射掉之后连本窗口都点不了。

## 2. 按键与触发

| 按键 | 说明 |
| --- | --- |
| 左键 / 右键 / 中键 | 标准三键 |
| 侧键 1 / 侧键 2 | 前进 / 后退键（`XBUTTON1/2`） |
| 滚轮上滚 / 下滚 | 把滚轮方向也当成按键拦截 |
| 语音键（长按） | 仅魔声 AI 垂直鼠标（`248A:60AB`） |

触发方式：

- **按下触发**：物理按下立即执行（默认；滚轮也用它）
- **按住（松开结束）**：只用于语音键，按住说话、松开识别

## 3. 事件类型

| 类型 | 配置 | 示例 |
| --- | --- | --- |
| 鼠标功能 | 单击 / 双击 / 长按 / 滚轮 | 左键双击、右键长按 0.6 秒、侧键 1 单击 |
| 键盘按键 | 组合键，可点「捕获按键」录制 | `ctrl+c`、`ctrl+shift+esc`、`alt+f4`、`win+r`、`f5` |
| **系统动作** | 从 31 项预设里选一个 | 后退、前进、播放/暂停、下一曲、音量加减、静音、复制粘贴、锁屏 |
| 打开应用 | 程序/快捷方式路径 + 可选启动参数 | `C:\Windows\notepad.exe`、某个 `.lnk` |
| 组合事件 | 有序步骤：按键 / 鼠标 / 打开应用 / 等待 | 先 `ctrl+c`，等 100ms，再点左键 |
| 宏定义 | 与组合事件相同，额外支持「输入文字」 | 打开记事本 → 输入文字 → 保存 |
| 语音输入 | 仅魔声语音键 | 按住语音键说话，松开后键入焦点输入框 |

### 3.1 系统动作（前进后退 / 媒体控制等）

预设 31 项，不用自己查虚拟键码，分五类：

| 分类 | 动作 |
| --- | --- |
| 浏览器 / 资源管理器 | 后退、前进、刷新、停止加载、打开搜索、打开收藏夹、浏览器主页 |
| 媒体与音量 | 播放 / 暂停、下一曲、上一曲、停止播放、音量增大 / 减小、静音切换、打开媒体播放器 |
| 窗口与桌面 | 显示桌面（`win+d`）、切换窗口（`alt+tab`）、任务管理器（`ctrl+shift+esc`）、截图（`win+shift+s`）、锁定屏幕 |
| 编辑快捷键 | 复制、粘贴、剪切、撤销、重做、全选、保存、查找 |
| 标签页 | 新建 / 关闭 / 恢复关闭的标签页 |

实现上有两类：

- **单键类**（浏览器、媒体、音量）直接发**扩展键**：`SendInput` 时必须带
  `KEYEVENTF_EXTENDEDKEY`，否则前台程序收不到——这是这类键最常见的坑；
  锁屏走 `LockWorkStation()`，不模拟快捷键
- **快捷键类**（编辑、标签页、窗口）复用现成的 `send_key_combo`，
  对**当前焦点窗口**生效

> 因为走系统通道，浏览器前进后退不依赖具体浏览器；但个别播放器不响应
> 多媒体键时属正常现象（由该程序自身决定是否处理）。

组合事件/宏定义的每一步都可以设置**「之后等待」毫秒数**；
「等待」步骤本身只等待、不执行动作。

> 宏里先「打开应用」再「输入文字」时，建议在中间加一个等待步骤（例如
> 500~1000ms），等窗口真正到前台后再输入，否则文字可能落到原来的窗口。

键盘组合支持：

- 修饰键：`ctrl` `shift` `alt` `win`，以及 `lctrl/rctrl/lshift/rshift/lalt/ralt/lwin/rwin`
- 常用键：`enter` `esc` `tab` `space` `backspace` `delete` `insert`
  `home` `end` `pageup` `pagedown` `left/up/right/down` `f1`~`f24`
  `numpad0`~`numpad9` `volumeup/down/mute` `media*` `capslock` 等
- 单字符：`a`~`z`、`0`~`9`、`` ` `` `-` `=` `[` `]` `\` `;` `'` `,` `.` `/`

## 4. 语音输入（仅魔声鼠标语音键）

语音输入被有意限定为**只能绑定语音键**，原因是有实测依据的：

- 0xFF91 的 `0x1B` 音频帧只在**按住语音键**期间上报；
  其他按键不会让鼠标开始收音（见
  [AiMouse 语音链路逆向笔记](AiMouse-RE-Notes.md) 第 5 节 Frida 记录：
  1528 条音频帧集中在按键的 5.35 秒内，全部来自同一句柄）。
- 因此把「语音输入」绑到侧键并不能凭空产生麦克风音频；UI 只给
  魔声设备显示「语音键」，且该键只能选「语音输入」。

使用步骤：

1. 选中「魔声 AI 垂直鼠标」→ 启用此鼠标 → 添加映射；
2. 按键选「语音键（长按）」，事件选「语音输入」；
3. 点好目标输入框（浏览器、记事本、聊天窗口等）；
4. **按住鼠标语音键说话，松开**；识别结果会键入刚才的输入框。

识别参数（模型、流式/整段、门控、收尾精修）沿用「语音窗口 → ⚙ 设置」里的
`voice_config.json`。语音输入组件在 `voice_service.py`，不依赖 Tk，
鼠标映射守护进程直接调用；语音窗口本身也复用同一套 `Recorder`/`AsrEngine`。
按键映射的语音输入**只负责识别并键入，不保存 WAV**；需要留档时用语音窗口监测。

> 不建议同时开着语音窗口的「开始监测」和本映射：两者都会读 0xFF91，
> 可能各自触发一次识别。
>
> 语音输入绑定启用期间，后台会持续读取 0xFF91（约 12 次/秒）以等待语音键，
> 功耗会比平时略高；长期不用时删除该绑定或关闭「启用此鼠标的映射」即可。

## 5. 后台运行

映射由独立进程负责：

```bat
python main.py --tool mouse-remap          :: 前台调试
python main.py --tool mouse-remap --status :: 看状态
python main.py --tool mouse-remap --stop   :: 停止
python main.py --tool mouse-remap --diagnose
```

- 单实例（命名互斥 `Local\ExtBatteryTrayMouseRemap`），不会重复装钩子
- 主面板/托盘启动时，如果配置启用且有绑定，会自动拉起守护进程
- 配置变化由守护进程轮询 `mouse_map.json` 的 mtime 热重载
- 状态写在 `%APPDATA%\ExtBatteryTray\mouse_map_status.json`
- 关闭配置窗口不影响映射；**完全退出应用（含托盘）**会停止后台映射；
  只最小化到托盘 / 只关配置窗口不会

## 7. 实现与限制

- **设备识别**：Raw Input 能区分 `VID:PID`，但不能拦截；`WH_MOUSE_LL`
  能拦截，但不带设备信息。两者放在不同线程：
  - 钩子只对「至少有一台启用设备绑定了这个按键」的事件工作；
  - 钩子最多等 **12ms**，让 Raw Input 线程送来同一次物理按键，再决定
    吞掉还是放行；
  - 识别不到设备时，只有「仅连接了一台鼠标」的保守场景才按映射处理，
    避免多鼠标时误吞别的鼠标；
  - Raw Input 仍能看到被钩子吞掉的点击（已用注入事件实测），所以这个
    关联不依赖「钩子放行」。
- 多鼠标 + 极低延迟场景下关联可能失败，失败时**放行原事件**（宁可漏一次
  映射，也不误吞）。`mouse_map_status.json` 的 `unmatched` 会累计次数。
- 设备按 `VID:PID` 区分：**两只完全同型号的鼠标会被当成同一台**，
  Raw Input 无法进一步区分；这种场景下映射会同时作用在两只上。
- 映射左/右键前请想清楚：配置窗口会自动暂停，退出窗口再恢复；
  如果映射到「打开应用」等动作，点击本工具窗口也会触发。
- 以**管理员身份运行**的窗口：普通权限的钩子收不到它在前台时的输入，
  `SendInput` 也会被 UIPI 拦下；需要以管理员身份运行本工具才能覆盖这类窗口。
- 锁屏 / UAC 安全桌面不接收用户态钩子与注入，属系统限制。
- 直接读 Raw Input 独占鼠标的游戏/程序可能绕过桌面钩子（系统不再走
  `WM_*BUTTON*` 消息），这类程序里映射可能无效。
- 低层鼠标钩子会收到每个移动报告（只是快速放行）；8K 回报率鼠标开启映射
  时 Python 回调的 CPU/延迟会略增，建议只映射实际需要的按键。
- 滚轮只支持上/下，不支持左右 tilt。
- 语音输入只支持魔声鼠标和语音键；其他鼠标没有可用的音频通道。
- **尚未实现**（按当前需求暂缓）：语音控制（转文字后交给 DSH 新对话）与
  语音翻译。后续计划：
  - DSH：调用 `dsh headless "<文字>"` 新建会话并后台执行；
  - 翻译：优先免费在线接口（MyMemory / Google gtx / LibreTranslate），
    失败回退本机 DSH；语言检测按 CJK 字符比例判断中/英。

## 8. 扩展新事件类型

事件类型是数据驱动的，新增一种只需改这几处：

1. `mouse_remap.ACTION_TYPES` 加 `(type, 中文名)`；
2. `normalize_action()` / `validate_action()` 增加该类型的字段与校验；
3. `execute_action()` 增加执行分支；
4. `mouse_mapping_panel.BindingDialog._render_body()` 增加参数编辑区；
5. 补 `tests/test_mouse_remap.py` 的配置/校验用例。

**同类动作不必新增类型**：像「系统动作」那样，加一项预设只需在
`SYSTEM_ACTIONS` 里补一行 `(id, 中文名, 规格)`，规格三选一——
`("vk", 虚拟键码)` 发扩展单键、`("combo", "ctrl+x")` 走快捷键、
`("call", 名称)` 调 Win32 API；校验、执行、界面下拉、列表摘要都会自动跟上。

语音控制（DSH）与翻译会按这个方式接进来，不需要动 Hook / 守护进程。

## 9. 排错

| 现象 | 检查 |
| --- | --- |
| 点「启用按键映射」后没反应 | 关闭配置窗口（配置期间自动暂停）；看状态是否 `运行中` |
| 状态 `钩子✗` | 可能被安全软件拦截 `SetWindowsHookEx`；换普通权限/重启 |
| 按键没被拦截 | 确认该设备勾了「启用此鼠标」，且该按键已绑定；看 `unmatched` |
| 映射后鼠标点不动 | 用键盘关闭配置窗口，或 `python main.py --tool mouse-remap --stop`，再改配置 |
| 语音输入没出字 | 确认是魔声设备、绑定的是语音键；语音窗口设置里模型是否可用 |
